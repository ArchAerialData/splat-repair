# Deep Fill setup

Run `install.cmd deep` from the repository root. To add only the Python Deep
Fill dependencies to an already installed editor, run:

```powershell
core\.venv\Scripts\python.exe core\setup_deep.py
```

The Desktop, Start Menu and taskbar shortcuts all launch the same app, whose
engine uses `core/.venv`. Close and reopen the editor after installation so it
probes the new capabilities. Select a small surface patch, choose **Deep Fill**,
leave **LaMa, wide view** selected, and press **Repair**. Inspect the result from
several angles; Undo restores the previous scene. Installation does not modify
any scan or perform automatic cleanup.

## Reproducible environment

The installer pins PyTorch 2.9.1 with CUDA 12.8, torchvision 0.24.1, gsplat 1.5.3,
simple-lama-inpainting 0.1.2, OpenCV headless 4.13.0.92 and fire 0.5.0. NumPy and
Pillow remain shared with the base engine. LaMa's package metadata contains old
upper bounds for those libraries and asks for GUI OpenCV; setup deliberately
installs its runtime dependencies explicitly. `pip check` therefore reports
those known metadata mismatches. An actual masked-image inference, rather than
package import alone, is the compatibility check.

On Windows, `setup_cuda.py` downloads the official NVIDIA CUDA 12.8.1 compiler,
runtime headers/libraries and CCCL archives. It verifies pinned SHA-256 hashes,
extracts into a staging directory, validates the layout, then publishes the
complete toolkit. Download size is 126.9 MB and extracted files total about
375.7 MB. It does not install a graphics driver, alter the registry or modify
the global PATH. Existing Visual Studio 2019/2022 C++ tools and Windows SDK
are still required.

Sources: [NVIDIA redistribution manifest](https://developer.download.nvidia.com/compute/cuda/redist/redistrib_12.8.1.json),
[PyTorch version pairing](https://pytorch.org/get-started/previous-versions/),
[LaMa model release](https://github.com/enesmsahin/simple-lama-inpainting/releases/tag/v0.1.0).

## Storage and desktop startup

- Python packages: `core/.venv/Lib/site-packages`.
- Local CUDA compiler: `core/.venv/cuda/v12.8`.
- LaMa weights: `core/models/torch/hub/checkpoints/big-lama.pt`, unless the user
  explicitly sets `TORCH_HOME` or `LAMA_MODEL`.
- Installer downloads: `.cache/pip` and `.cache/cuda` (or an explicit pip cache).
- Compiled gsplat extension: PyTorch's per-user extension cache. The first
  compilation can take several minutes; subsequent launches reuse it.

The engine initializes the local CUDA path and a supported x64 C++ build
environment before importing gsplat. It compiles for the GPU used by the
engine, respecting an explicit `TORCH_CUDA_ARCH_LIST`. This avoids compiling
for an unrelated older secondary graphics card. No developer terminal is
required for the normal shortcut launch.

## Verification

Setup now fails with a nonzero exit code if any dependency installation,
compiler download, GPU render or LaMa inference fails. OpenCV fallback does
not count as a working LaMa installation.

Run the production editor integration check from `app` after building:

```powershell
npx electron smoke/deep-fill.cjs
```

It uses an isolated profile and a generated surface. It checks the GPU/LaMa
controls, performs a real Deep Fill through the UI and engine protocol, and
checks Undo. A refinement may legitimately be rejected by the quality guard;
the report distinguishes execution success from that quality decision. It
does not establish quality or memory requirements for a large real site.

### Verified locally on 2026-11-19

- RTX 4080 SUPER, PyTorch 2.9.1+cu128, MSVC 14.44 and app-local CUDA 12.8.
- First gsplat compilation completed in about 266 seconds; real CUDA rendering
  succeeded. A repeat run of the complete installer succeeded without rebuilding.
- A real LaMa masked-image fill passed using the project model cache.
- Production editor smoke test: GPU/LaMa controls enabled, 111 splats selected,
  125 removed and 144 generated by a real LaMa wide-view repair in 7.222 seconds.
  The 250-step GPU fit completed and its refinement was accepted. No fallback
  or renderer errors occurred. Undo restored all 6,561 original splats.
- Seven installer tests and 14 environment tests passed, along with orientation,
  format, Python syntax and smoke-script syntax checks.
- The existing pinned shortcut was read back and launched successfully with
  the expected application ID. Its target, arguments and icon already point to
  this checkout. Native desktop capture timed out; the control-state checks
  above were performed in the isolated production editor test.

Measured storage after setup: engine environment 5.449 GB (including existing
base packages and local compiler), model weights 0.206 GB, reusable installer
caches 3.058 GB, compiled extension 0.054 GB. These are this machine's logical
file sizes, not universal installation requirements.
